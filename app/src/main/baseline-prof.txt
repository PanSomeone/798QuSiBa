# Baseline profile: this app's own start-up path, and nothing else.
#
# Why a hand-written one instead of a generated one
# -------------------------------------------------
# The normal way to produce this file is the `androidx.baselineprofile` Gradle
# plugin, which drives a Macrobenchmark on a device and emits a profile from what
# it observed. That path needs `androidx.benchmark` to be downloaded, and this
# project's dependency set is deliberately small. Guessing the whole app's hot
# paths would be worse than no profile at all — a wrong entry costs dex size and
# buys nothing — so this file is scoped to the one thing that can be reasoned
# about and *checked* without measuring: the chain from process start to the first
# frame.
#
# Every signature below is checked twice, and both checks are needed because they
# catch different mistakes.
#
# `tools/check-profile.py --classes` reads the method table out of
# `app/build/intermediates/compile_app_classes_jar/debug/.../classes.jar` and
# compares the name and the parameter count against what the compiler emitted. It
# catches a descriptor that was written wrong.
#
# `tools/check-profile.py --mapping` reads `app/build/outputs/mapping/benchmark/
# mapping.txt` after R8 has run, and reports the entries that no longer name
# anything in the built program. It catches a descriptor that was *right* and has
# since stopped mattering, which is the failure mode that matters here: R8 inlines
# and deletes, so an entry can be correct in the source and absent from the APK.
#
# Both checks exist because the first version of this file was written from memory.
# Six of its lines -- including four that named accessors on `Palette` for objects
# that are separate top-level declarations -- matched nothing at all, and a profile
# entry with the wrong descriptor is not an error and not a warning: dexopt and R8
# both drop it silently, so it costs the dex size of looking like intent and buys
# nothing.
#
# The chain it covers
# -------------------
# `KillHuiShengHuoApp.onCreate` builds the object graph and the two
# SharedPreferences stores → `MainActivity.onCreate` → `AppRoot` → the theme,
# then `HotWaterScreen` and the tab bar, with `HotWaterViewModel` constructed
# during that first composition and reading the device list. Nothing in the
# settings, login or log screens is reachable before the first frame, and they
# are deliberately absent.
#
# Library entries are deliberately absent too. Compose's own hot methods are the
# part a generated profile is actually for, and the ones on this path are mostly
# `inline` in Kotlin, which means the entry would point at a method R8 has
# already removed. `tools/PERFORMANCE.md` says what that costs and what would fix
# it.
#
# What makes it land in the APK
# -----------------------------
# The file has to sit exactly here — `src/main/baseline-prof.txt`, not in
# `src/main/assets`. AGP compiles it into `assets/dexopt/baseline.prof` while
# packaging. From there the ART Service picks it up at install time on Android
# 12+, and `androidx.profileinstaller` (already a transitive dependency, 1.4.0)
# installs it on the older releases this app still supports — `minSdk` is 26, and
# without the installer everything below API 31 would ignore the file entirely.

# The palettes and the scales. `KhsTheme.kt` reads these while building the
# schemes, which happens once per process on the way to the first frame.
#
# `KhsTheme.kt` reads from `Palette`, not from `LightPalette`: the dark scheme is
# what the first frame draws. `Radii`, `Spacing` and `Motion` are not here either,
# and the reason is worth keeping, because it will look like an omission.
#
# `tools/check-profile.py --mapping` reads R8's mapping for the built program and
# reports what survived. All four are gone from it, for two different reasons:
#
#   * `Radii` and `Spacing` are `object`s of `val`s with a literal initialiser, so
#     the compiler inlined every use and R8 deleted the classes outright. Their
#     entries named a class the shipped APK does not contain.
#   * `LightPalette` and `Motion` still appear in the mapping, but only as inline
#     frames: every one of their properties was inlined into a caller and the
#     declarations were then removed. `Motion.spring()` is such a small generic
#     function that it inlines into the tab bar, and nothing on the start-up path
#     ever reads `LightPalette` at all -- the app starts dark.
#
# Those five lines were dropped rather than left in place. An entry that cannot
# match is not free: it reads as intent, so the next person keeps it, and dex size
# is the only thing it ever buys.
HSPLcom/killhuishenghuo/ui/theme/Palette;-><clinit>()V
